> 生成日期：2026-09-12
> 原则：Demo 是一场可见的学习过程，不是功能菜单。评委只看一件事——它有没有可能变成一个用户离不开的产品。
> 数据标注：**[现场输入]** = 评委看着敲进去 / **[预置样例]** = 赛前用真实修改稿导入生成 / **[演示辅助]** = 为演示流畅而准备，答辩时如实说明

## 1. 现场 Demo 闭环（约 3 分钟）

### 前置状态
- 工作区「品牌 A」已导入 2 组真实原稿/修改稿 **[预置样例]**，记忆库有 2 条已确认规则。
- 工作区「品牌 B」已导入另一位队员的 2 组真实修改 **[预置样例]**，记忆库有 2 条规则，其中至少一条与 A 方向相反。
- 日志页已有赛前真实迭代记录（含一次误判 → 纠正）。

### 分镜

| 时间 | 展示什么 | 输入 | 用户动作 | 系统状态变化 | 评委应理解什么 |
|------|---------|------|---------|-------------|--------------|
| 0:00–0:20 | P1 导入页 | 原稿："保证让你的工作效率提升十倍" / 修改稿："减少重复整理资料的时间" **[现场输入，从队员真实稿件中取]** | 粘贴、选场景"公开宣传"、点提取 | 生成 diff `D-xxx`，调模型 | 数据入口是真实修改，不是规范文档 |
| 0:20–0:50 | P2 候选确认页 | — | 看到候选："对外效果承诺需要限制"，两个解释：① 避免缺乏证据的效果承诺 ② 整体表达更克制。每个解释下有反例预演："若选①，'根据项目数据减少 32%'将通过；若选②，将被提示" | 选 ①，范围勾"公开宣传、产品介绍"，处理选"长期" | 记忆 `J-003` 状态 candidate → confirmed | 系统提出假设，人决定意图和边界；模型不直接写规则 |
| 0:50–1:20 | P3 审核页 | 新稿 1（含："帮你提升十倍效率""根据 2025 年内测数据，平均减少 32% 整理时间"）**[现场输入]** | 选场景"公开宣传"，点审核 | 顶部显示"加载 2 条规则，跳过 0 条"；第 1 句被拦，第 2 句通过 | 学到的是"无依据的承诺"这个条件，不是"禁止数字" |
| 1:20–1:40 | 点开第 1 句发现卡 | — | 点展开 | 显示四段式：冲突标准 J-003 v1 / 依据：D-xxx before→after / 你当时确认：解释① / 建议 | 每条建议可追溯到具体修改原文 |
| 1:40–2:10 | 反馈 + 例外 | 新稿 2：报名提醒"最后 3 天，名额有限，立即报名" **[现场输入]** | 选场景"报名截止提醒"，审核 → 若品牌 A 有"不使用催促表达"规则且范围含此场景，被拦 → 用户点"这次是例外" | `exceptions[]` 追加一条；规则本体不变；日志写入 | 例外被记录但不改标准 |
| 2:10–2:35 | 再审证明例外未污染 | 新稿 3：公开宣传稿含"赶快抢购" **[现场输入]** | 选"公开宣传"，审核 | 催促表达仍被拦，显示"J-005 v1，1 次例外记录（报名提醒场景）" | 例外没有污染长期标准 |
| 2:35–3:00 | P5 对照页 | 新稿 1 | 切到品牌 B | 同一稿：品牌 B 不拦"提升十倍"（B 允许强销售表达），但拦另一句竞品比较 | 同一套系统，不同历史，不同结论——这就是"未定信号" |

### 加分动作（如时间允许，30 秒）
- 请评委任改一句新稿文本，重新审核，展示结果随输入变化。**[现场输入]**
- 切到 P6 日志页，展示赛前真实发生的 v1"避免使用数字" → 用户拒绝 → v2"无依据效果承诺需限制"的时间线。**[预置样例，真实记录]**

### Demo 失败备用路径
- 模型 API 超时：UI 显示"使用最近一次成功结果（缓存于 HH:MM）"，口头说明，不伪装实时。
- 完全无网：播放赛前录屏，开头就说"以下为昨晚 XX 点真实运行录屏"。
- 候选提取返回 0 条：现场手动新建规则，顺势说"这就是人机分工——模型提不出来时人可以补，但模型提出来的必须人确认"。

## 2. 对照实验设计

### 实验条件（同一份未见过的新稿、同一基础模型）

| 组 | 输入 | 输出 | 说明 |
|----|------|------|------|
| A 裸模型 | 新稿 + 通用审稿提示词 | 审核意见 | 基线 |
| B 只喂历史 | 新稿 + 5 篇历史修改稿全文 + "请参考团队风格审核" | 审核意见 | **最关键的对照组**，直接回答"我把历史稿丢给模型不就行了" |
| C 分寸 | 新稿 + 经确认的结构化记忆（按 scope 过滤）| 四段式发现 | 实验组 |

### 评价
- 评价者：两位提供真实修改稿的队员，盲评（不知道输出来自哪组）。
- 每条输出回答三个问题：① 还需要我改几处？② 是否符合我的意图？③ 是否错误套用了规则（误伤）？
- 只展示原始计数表，不做百分比、不做显著性表述。

### 不能过度宣称的地方
- 样本 ≤3 篇新稿、2 位评价者，只能说"在本次演示中"。
- 如果 B 组表现接近 C 组，如实展示，并强调 C 组的差异在"可追溯 / 可推翻 / 范围控制"，而不只是审核质量。
- 评价者是队员本人，存在偏向，答辩中主动说明。

以下为**应当在开发过程中真实发生并记录**的事件模板。不要编造，每条必须有真实时间戳和日志 ID。

| 时间 | 事件 | 证明什么 |
|------|------|---------|

## 4. 答辩叙事

### 30 秒电梯陈述
> 很多 AI 能模仿你的语气，却学不会你为什么删掉那句话。分寸从你真实的原稿和修改稿里，提取你反复做的判断，经你确认后变成带条件、带来源、可推翻的团队审核记忆。下一篇稿子进来，它不只说"这句不好"，而是说"这和你上次确认的'效果承诺需要证据'冲突，依据是项目介绍第二版的那次修改"。用得越久越像你的团队，换一套数据，它就是另一套系统。

### 90 秒版本
在 30 秒版本基础上加：
> 我们做了三件别人抄不走的事：第一，模型只提候选，人来确认意图——所以它学到的是"无依据的承诺不行"，而不是"不能有数字"。第二，规则有范围，例外单独记录——公开宣传不能催促，报名提醒可以，例外不污染标准。第三，每条建议后端校验来源，编不出依据。现场我们会用同一篇稿子跑两位队员的真实记忆，让你看到结论怎么不同。

### 3 分钟 Demo 讲解词（配合分镜）
- 0:00 "先给它一次真实的修改。这是我们队员自己项目介绍的前后版本。"
- 0:20 "它没有直接写规则，而是问我：你是反对没有证据的承诺，还是想整体克制？我选前者。注意这里的反例预演——它告诉我选了以后哪种句子会过、哪种不会。"
- 0:50 "现在来一篇新稿，里面有'提升十倍'和'根据内测数据减少 32%'。它拦了前一句，放了后一句——学到的是条件，不是禁词。"
- 1:20 "点开看依据：来自哪次修改、原文是什么、我当时确认了什么。这不是模型编的，后端校验过规则 ID。"
- 1:40 "再来一篇报名提醒。它拦了'立即报名'，但这个场景我允许，我标一次例外。"
- 2:10 "然后再审一篇公开宣传稿——催促表达依然被拦。例外没有污染标准。"
- 2:35 "最后，同一篇稿子切到另一位队员的记忆——他允许强销售表达，所以'提升十倍'没被拦，但他拦了竞品比较。同一套系统，不同的人，不同的结论。"

### 5 分钟答辩主线
1. （30 秒）问题：负责人反复解释同一类判断，沉淀不下来，交不给人也交不给 AI。
2. （30 秒）为什么现有方案不行：规范文档写不全、提示词学的是措辞、RAG 检索的是相似文本而不是判断边界。
3. （2 分钟）Demo 闭环（压缩版）。
4. （1 分钟）四个评分维度对应：数据壁垒——换记忆换结论；可用性——现场真实输入跑通；过程记录——展示日志页真实误判与纠正；持续价值——逐轮指标条。
5. （30 秒）诚实边界：一天半验证了机制能跑通，没有证明长期护城河；样本小，只报实际数字。
6. （30 秒）收尾："请不要只看分寸今天能不能审一篇文案，请看它是否因为这个团队过去的判断，在下一篇里变得更准。"

### 评委可能追问的 10 个问题（简版，详见《问题与风险审计》第 2 节）

| 问题 | 一句话回答 |
|------|-----------|
| 和提示词+RAG 区别？ | 候选需确认、范围过滤在代码、例外独立存储、来源被校验——四件事 RAG 都不做 |
| 一次修改凭什么是标准？ | 不是。它只是候选，用户四选一；标准是被多次接受后才成立的 |
| 数据壁垒在哪？ | 规则的来源对照、被推翻/例外的历史、实际接受率——只能从使用中积累 |
| 换团队真的不同？ | 不只是禁词表不同，判断方向可以相反，现场看对照页 |
| 归因错了怎么办？ | 会错，Demo 就展示这个错怎么被纠正 |
| 例外多了规则失效？ | 例外不改规则本体，≥2 次才提议改范围，仍需确认 |
| 用户凭什么持续反馈？ | 反馈嵌在本来就要做的审稿动作里，不是额外任务 |
| 一天半能证明持续价值？ | 只能看趋势，我们报实际数字不报百分比 |
| 隐私？ | 本地 JSON，队员授权文案 |
| 为什么不微调？ | 微调学风格，不可追溯不可推翻 |

## 如果只能再做三件事
第一，拿到真实修改稿——没有它一切都是剧本。第二，把范围过滤、例外隔离、rule_id 校验做在代码层，并在 UI 上显示"加载 N 条、跳过 M 条"——这是回答"为什么不是提示词 + RAG"的唯一硬证据。第三，从第一次运行起就落盘日志，让至少一次真实的误判 → 纠正 → 再审生效被记录下来——这同时覆盖过程记录和持续价值两个维度。
