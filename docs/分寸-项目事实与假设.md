## 1. 已确认事实 [业务事实]

### 1.1 赛道要求
- 赛道名「未定信号」：做一个"别人抄不走、你自己离不开"的 AI 产品；同一套系统喂进不同人的数据产出完全不同。
- 四个自检问题：真实问题、独有数据、个体差异、长期价值。
- 去掉测试：去掉私有数据是否退化为通用工具；去掉 AI 用户是否难以独自处理同样规模的工作。
- 评委只看一件事：这东西有没有可能变成真实用户离不开的产品，而不是一个 demo。
- 演示建议：先用一个人的真实数据正常跑，再换一份完全不同的数据对照；如时间允许展示"喂了一段时间 vs 刚开始"的差距。
- 四个参考方向：专家判断复刻、报价参谋、流失雷达、招聘校准。共同要求：使用授权数据、保护个人及商业信息、AI 输出可解释/核验/修正。

### 1.2 评分维度
- 四个维度：数据壁垒、产品可用性、过程记录、持续使用价值。
- 已知权重：过程记录 25%。其余三项权重未知。
- 数据壁垒被材料称为"最高分项"[材料原话，权重未证实]。
- 产品可用性要求：能接收真实数据、完成核心流程、给出可验证结果；避免静态页面或预置答案；最好现场改一句文本。
- 持续价值要求记录三个指标：重复问题是否减少、需手动解释的判断是否减少、接受建议比例是否提高。
- 最终展示必须出现三个动作：同一输入不同记忆不同结果；用户推翻一次错误判断后系统表现改变；第二/三次审核比第一次少需人工解释。

### 1.3 「分寸」产品概念
- 核心定位（已收紧版）：把一个团队反复修改时做出的判断，沉淀成带条件、带证据、可纠正的审核系统。
- 唯一流程：导入原稿+修改稿 → 提取候选判断 → 用户确认适用范围 → 审核新稿并展示依据 → 从新的修改继续更新。
- 三个做深点：学"为什么改"而非措辞；记忆有条件且可推翻；新任务中主动用起来且说得出依据。
- 候选判断必须四选一确认：长期适用 / 仅当前项目 / 这次例外 / 暂不记录。
- 反馈动作压缩为：接受 / 拒绝 / 这次是例外 / 适用范围调整。
- 输出格式：问题句 → 冲突的标准 → 历史依据 → 可执行建议。
- 核心验证指标：第二次审核时用户是否少解释了一遍同样的问题，并愿意相信系统给出的依据。
- 主方向：专家判断复刻；不套其他三个方向。

### 1.4 团队与资源
- 团队成员全部为 AI 产品经理，传统开发经验有限。
- 可通过 Claude Code Vibe Coding 完成代码、测试、前后端、部署。
- 赛程约一天半 [思路文档中的假设，新提示词沿用]。

## 7. 可以用团队成员现场真实产生的数据验证的内容

| 可验证的内容 | 需要的数据 | 谁产生 |
|-------------|-----------|--------|
| 候选判断提取是否合理 | 3 组原稿/修改稿 + 逐条理由 | 队员 A 写方案，队员 B 评审修改 |
| 意图二选一是否区分了"学条件"与"学禁词" | 1 组含"无基线百分比"→"有测量方法"修改的样本 | 队员 B |
| 范围过滤是否生效 | 1 份探索期方案 + 1 份上线前 PRD | 队员 A |
| 例外是否污染 | 标记一次例外后再审同类文档 | 队员 B 操作 |
| 换评审人换结论 | 队员 C 以不同标准修改 ≥2 组 | 队员 C |
| 人工解释次数逐轮变化 | 3 轮审核的日志 | 系统自动记录 |
| 拒绝→改版→再审生效 | 1 次真实拒绝 | 队员 B 操作 |

**注意**：以上数据全部是"现场真实产生"，不是"历史数据"。答辩表述必须是："分寸通过几次真实的方案修改，在现场形成并验证最小审核记忆。"
