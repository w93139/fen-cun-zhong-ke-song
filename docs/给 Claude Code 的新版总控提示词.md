```text
## 第三阶段：设计无历史数据的真实验证闭环

请设计一套由团队成员真实完成的最小数据生成与验证流程：

1. 一位成员提供真实做过或现场认真设计的一份 AI 产品方案；
2. 另一位成员以真实评审人的身份修改它；
3. 保存原稿、修改稿、逐条修改理由和修改者身份；
4. 系统只提出候选判断，不直接把候选当成规则；
5. 审核人确认、拒绝、标记为本次例外，或调整适用范围；
6. 使用第二份新方案进行审核；
7. 用户纠正一次错误判断；
8. 使用第三份新方案验证纠正是否生效，以及例外是否污染长期规则；
9. 同一份新方案切换两套真实形成的审核记忆，证明结果不同。

要求：
- 至少 3 组真实原稿/修改稿；
- 不得手写几条规则再伪装成历史学习；

- 反馈动作至少支持接受、拒绝、例外、调整范围；
- 拒绝不等于删除，必须保留可追溯的版本记录；
```

