# 「分寸」技术适配声明

> 生成日期：2026-09-12 · 阶段五产出 · 格式遵循《AI Agent 产品 Vibe Coding 通用技术栈手册》第六节
> 本声明**不做开放式技术选型**，默认采用手册基线，仅对触发适配条件的项说明偏离。
> 产品经理只需确认三件事：① 对产品和阶段的理解是否正确；② 是否新增了未要求的费用/平台/范围；③ 暂缓项是否影响本阶段验收。

---

## 1. 产品形态判断

- **产品类型与核心任务**：单用户本地 Web 工具。用户导入 AI 产品方案「指标与验收标准」章节的原稿与修改稿，系统提出候选判断，用户确认后形成审核记忆；再用该记忆逐句审核新方案，用户反馈（接受/拒绝/例外/调范围）持续更新记忆。
- **核心交互**：**分阶段确认**。人工确认是产品价值的一部分（候选→确认、发现→反馈），不是附属弹窗。
- **开发路径**：**纵向切片**。理由：手册第一节明确"人工确认是 Agent 能力的一部分时应采用纵向切片"；本产品若后端先行，无法在无界面的情况下验证"用户确认后系统行为改变"这一核心命题。
- **当前阶段范围**：比赛 MVP——本地运行、单用户、两个工作区（两位评审人）、一条端到端闭环、可现场演示。**不含**公网部署、登录、多用户、数据库。

## 2. 采用的默认方案

| 方案 | 采用原因 |
|------|---------|
| Python 3.11.x | 手册默认；Vibe Coding 生态最成熟 |
| FastAPI | 手册默认；自带 OpenAPI 文档便于验收 |
| Pydantic v2 | 手册默认；同时用于 API 校验和**模型结构化输出校验**（本项目强制底线） |
| pytest | 手册默认；解析器、范围过滤、例外隔离、版本更新全部是纯函数，最适合单测 |
| Git | 强制底线 |
| `.env` + `.env.example` | 强制底线；密钥只在后端读取 |
| 官方 SDK 或 OpenAI 兼容接口调用模型 | 手册默认；模型名、base_url、超时通过配置读取 |
| 带 schema 版本的 JSON 文件持久化 | 手册第三节：单用户、本地、简单索引时可用文件清单；本项目数据 = 2 个工作区 × 几十条规则 |
| Prompt 独立文件管理（`services/prompts/`） | 强制底线 |
| 双层测试（mock 自动化 + 真实模型冒烟） | 强制底线 |
| 最小验收界面 = 单 HTML 放 `backend/app/static/`，FastAPI 挂载 | 手册第五节默认实现 |

## 3. 触发的按需模块

| 模块 | 触发需求 | 本阶段是否引入 |
|------|---------|--------------|
| 句级 diff | 提取候选判断需要原稿/修改稿的句级对齐 | 引入，用标准库 `difflib`，不引入第三方 |
| append-only JSONL 日志 | 过程记录 25% + 指标采集 | 引入，标准库 |
| 原子写入（写临时文件后 rename） | 强制底线：结构化文件持久化必须原子写入 | 引入，标准库 |
| SSE / 异步任务 | 单次模型调用预计 5–15s，属于"短请求"边界 | **不引入**；用同步请求 + 前端 loading 状态 + 30s 超时。若冒烟发现单次 > 20s，改为"提交 + 轮询"（见第 4 节恢复条件） |
| SQLite + SQLAlchemy | 多实体关系/并发/账户 | **不引入**；无多用户、无并发 |
| Chroma / 向量检索 | 语义检索 | **不引入**；规则数量 < 50，按 scope 标签过滤后全部塞入上下文 |
| python-docx / pypdf | 文档解析 | **不引入**；输入为粘贴文本 |

## 4. 偏离或暂缓的默认方案

| 默认方案 | 替代方案 | 原因 | 影响 | 重新评估条件 |
|---------|---------|------|------|------------|
| **Next.js + TypeScript strict + Tailwind 正式前端** | 单个 `index.html` + 原生 JS + 内联 CSS 设计变量，由 FastAPI 挂载 | ① 新提示词允许"更小的单页原型更适合"时替代；② 一天半赛程、非技术团队，Node 工具链 + 构建 + 类型错误是主要失控风险；③ 前端手册第 5.1 节"产品只需要一个很小的嵌入式页面"属于允许改用其他方案的情形；④ 手册第五节：若交互属于核心，可作为正式前端第一条纵向切片——本项目 6 个视图全在一页内切换 | 无组件库、无路由、无 TS 类型检查；需手写状态管理；移动端仅保证 390px 可读不保证可操作 | 比赛结束后若产品继续，且页面数 > 3 或需多用户，迁移到 Next.js。**比赛期间即使有富余时间也不迁移**，只在同一页面内打磨 |
| `/api/v1` 前缀 | `/api` | 手册允许内部 MVP 先用 `/api` 并集中定义 | 无 | 对外发布时加版本 |
| 火山引擎 veFaaS 部署 | 本地 `uvicorn` 运行 | 部署手册明确是"前后端验证通过后"的续篇；比赛 Demo 在本机 | Demo 依赖本机 + 网络 | 比赛后如需公网访问再按部署手册执行 |
| Agent Loop（s01）自主循环 | 代码状态机 + 固定顺序的 2–3 次模型调用 | 手册第九节 3-[B]："固定业务流程默认由代码状态机编排"；本项目流程完全固定，不需要模型动态选工具 | 无自主性——这是有意为之 | 无 |
| 前端手册 Vitest / Playwright | 不引入前端自动化测试；用浏览器人工验收清单 + 后端 pytest 覆盖全部逻辑 | 前端只是薄壳，所有判断逻辑在后端 | 前端回归靠人工 | 迁移 Next.js 时补 |

## 5. 强制底线检查

| 底线 | 状态 | 具体措施 |
|------|------|---------|
| 密钥与隐私 | 待处理（开发时落实） | 模型 Key 仅 `.env`；`.gitignore` 含 `.env`、`data/`；日志不记 Key、不记完整方案原文（只记句 ID + 前 20 字摘要）；前端无任何密钥 |
| 数据与任务可恢复 | 待处理 | 工作区 JSON 带 `schema_version`，原子写入；每次写入前备份上一版到 `data/backup/`；服务重启后从文件恢复全部状态；人工确认点（候选待确认、发现待反馈）持久化在文件中，刷新页面可继续 |
| 输入输出校验 | 待处理 | 所有 API 请求/响应 Pydantic 模型；模型输出 → 确定性解析（宽容 JSON 提取）→ Pydantic 强校验 → 失败重试 1 次 → 仍失败返回统一错误并允许人工新建；**rule_id 由代码校验存在性**，无效引用降级为"通用建议" |
| 错误与日志边界 | 待处理 | 统一错误结构 `{"error": {"code", "message"}}`；不回显堆栈；模型超时 30s，重试 1 次 |
| 测试与真实模型验收 | 计划 | 第一层：pytest 覆盖 diff、候选解析、scope 过滤、例外隔离、版本更新、rule_id 校验、指标计算、原子写入；第二层：每类模型调用（提取 / 反方验证 / 审核）各至少一次真实冒烟，记录模型、耗时、结构合规率；无 Key 时明确声明待验，不用 mock 冒充 |

## 6. 需要产品经理决定的问题

只列会改变产品目标、成本、安全或交付范围的问题：

1. **模型厂商与 Key**：手册不固定模型。需要一个支持 JSON 结构化输出、中文能力好、现场网络可达的模型。请指定厂商/模型名并提供 Key（开发期可缺省，验收前必须有）。预计比赛期间调用量 < 200 次，成本可忽略。
2. **前端形态**：确认接受"单页 HTML 而非 Next.js"。这会影响 Demo 视觉精致度，但大幅降低一天半内失控风险。
3. **数据保存位置**：所有数据保存在项目 `data/` 目录本地文件，不上传任何第三方（除模型 API 接收待审核文本外）。请确认队员的方案文本可以发送给所选模型厂商。

其余项全部采用默认方案，无需逐项审批。

## 附：前端技术适配声明（精简版，遵循前端手册第 23 节）

- **项目判断**：单页工具 / 用户 = 队员本人 / 桌面 Web 优先，390px 可读 / 新项目 / 本阶段目标 = 一条闭环可视化
- **技术选择**：原生 HTML + JS + CSS 变量；无框架、无构建；`fetch` 集中在一个 `api` 对象；无流式；表单原生；无前端自动化测试
- **Agent 状态映射**（遵循前端手册第 9 节最低状态集合的子集）：
  - `idle` 未开始 · `submitting` 提交中（按钮禁用防重复）· `running` 模型处理中（显示"正在提取/审核…"）· `waiting_user` 等待确认/反馈（**一等状态**，高亮显示待处理项数）· `succeeded` · `failed`（统一错误文案 + 重试按钮）
  - loading / empty / failed 三态分开：候选为空显示"未提取到候选，可手动新建"，不显示"暂无数据"
- **等待用户确认方式**：候选卡片四选一 + 解释二选一；发现卡片四按钮；确认状态持久化在后端，刷新页面从后端恢复
- **取消/重试/恢复**：无后端取消（模型调用短）；失败可重试；刷新页面按 `workspace_id` 重新拉取全部状态
- **核心页面**（单页内 6 个视图切换）：工作区 → 导入 → 候选确认 → 审核 → 记忆库 → 对照 / 日志
- **产物类型**：JSON 结构化 findings，前端渲染为四段式卡片
- **响应式目标**：1280px 主验收；390px 可读
- **偏离手册**：不用 Next.js / TS / Tailwind / Lucide / Vitest / Playwright（原因见第 4 节）
- **待确认**：无（前端形态问题已在第 6 节提出）
