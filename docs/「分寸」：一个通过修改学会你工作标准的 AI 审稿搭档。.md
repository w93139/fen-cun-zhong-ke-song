# 「分寸」：一个通过修改学会你工作标准的 AI 审稿搭档。

先只服务一种人：**需要持续审核文案的品牌或内容负责人。**

这个人真正烦的事情，往往是：“这段太夸张”“这个承诺不能写”“我们不这样说话”，已经解释很多遍，每篇稿子还得再改。你们要解决的是这些反复出现、难以完整写成规范的判断。

第一版可以从团队成员自己的文章、项目介绍、对外文案切入。有没有真实的前后版本，是开工前最重要的检查。

产品只保留一条完整流程：

> 导入原稿和修改稿 → 提取可能的判断标准 → 用户确认适用范围 → 审核新稿并展示依据 → 从新的修改继续更新。
> 
> 

其中有三个地方值得做深。

**第一，学习“为什么改”，不只模仿措辞。**

例如用户把：

> “保证让你的工作效率提升十倍”
> 
> 

改成：

> “减少重复整理资料的时间”。
> 
> 

系统不能直接学成“用户不喜欢数字”，而应该提出一个待确认的解释：

> “你是在避免缺乏证据的效果承诺，还是希望整体表达更克制？”
> 
> 

用户选前者后，下一篇稿子里有依据的数字就应该保留。**这能区分真正学到判断标准，和粗糙地模仿修改痕迹。**

**第二，记忆要有条件，也要能被推翻。**

每条标准都应该能展开查看：

- 来自哪次修改；

- 用户是否确认；

- 用在什么场景；

- 有没有例外；

- 当前是否仍有效。

例如，“不使用催促性表达”适用于公开宣传，但不一定适用于报名截止提醒。出现冲突时，让用户澄清一次，再更新范围。

这部分能体现你之前关心的“人和 AI 如何分工”：AI归纳、发现冲突，人决定意图和边界。

**第三，新任务中主动用起来，而且说得出依据。**

审核新文案时，直接标出：

> “这一句与您此前确认的‘效果承诺需要证据’冲突。依据：项目介绍第二版中的修改。建议补充来源，或改成限定条件的表达。”
> 
> 

用户可以接受、拒绝，或标记“这次是例外”。这些动作继续成为数据，不需要额外写长篇复盘。

**为什么我觉得这个切口值得冲？**

它能在很短的时间内形成真实闭环：人修改一次，系统就在下一份新材料中接受检验。相比必须等待成交、流失或员工绩效的方向，你们有机会在比赛期间拿到真实证据。

但要承认一个弱点：\*\*只做“提取偏好＋保存提示词”，很容易被复制。\*\*你们需要证明的价值，是能准确捕获修改意图、处理适用条件、纠正错误记忆，并降低用户下一次审核的负担。一天半只能验证这个机制的潜力，不能证明已经建立长期护城河。

\*\*一天半，我会这样安排。\*\*以下以三人团队、约一天半赛程为假设；人数不同可以合并角色。

三个人分别负责产品与用户测试、学习与审核逻辑、前端与演示体验。**最后一个阶段必须留出来，别把全部时间用来开发。**

范围需要很狠地收住：单一文案场景、文本输入、一个模型、可追溯的记忆即可。多智能体、浏览器插件、企业接入、复杂账号系统，都不值得占用这次比赛的主要时间。

**冲奖最重要的准备，是一个经得起质疑的对照实验。**

第二组尤其重要。缺了它，评委很容易追问：“我把历史稿子直接发给模型，不就一样吗？”

让两位使用者在不知道输出来源的情况下判断：还需要改几处、是否符合本人意图、是否错误套用了规则。小样本结果只按实际展示，别包装成统计显著的提升。

**路演我会设计成一场可见的学习过程。**

1. 给同一份新稿，展示两位使用者的不同审核结果，以及各自证据。

2. 展示系统一次合理但错误的推断，比如误以为用户讨厌数字。

3. 用户澄清：“我反对的是没有依据的数字。”

4. 再给一段同时包含有依据和无依据数字的新文本，看它能否正确区分。

5. 展示对照结果，以及仍然失败的边界。

这里最有力量的不是输出多漂亮，而是评委看到了：**它可以理解错，但用户能够发现、纠正，并验证纠正是否生效。**

开工前设一个明确的止损点：\*\*两小时内拿不到真实修改记录，就不要继续做一个虚构品牌演示。\*\*用队员自己的项目介绍、文章或对外文案，现场留下真实修改，再测试新的材料；如果连持续审核的需求都没有，就换到团队确实反复做的工作。

我愿意押这个方向，原因是它把“独有数据、个体差异、持续积累、人机协作”放进了一个一天半能完成、也能现场检验的闭环里。你们要拿出来的核心证据是：**这个人刚刚教给它的判断，确实改变了它下一次工作的方式。**
